## 1. Problem Statement & Root Cause Diagnosis

### 1.1 Forensic Analysis Across Pilot 01 Attempts 1–7
Supervised Pilot 01 against the synthetic calculator fixture exposed recurring difficulties when relying on compact local coding models (`qwen2.5-coder:1.5b`) to provide both the search block (matching exact repository coordinates) and the replacement block:

1. **Attempt 1**: Scope mismatch — intake targeted test files, causing repair planning to attempt test mutation instead of modifying implementation code.
2. **Attempts 2–3**: Trailing commas in JSON responses and un-prefixed diff additions inside hunks (indented Python statements without `+` in column 0).
3. **Attempt 4**: Column 0 diff formatting failures persisted; unified diffs generated by compact models lacked genuine +/- hunk markers.
4. **Attempt 5**: Ollama grammar optimization completely omitted patch fields on the wire because Pydantic schemas allowed `None` defaults without wire-level `required` enforcement.
5. **Attempt 6**: Local model emitted structured output keys, but attempted to replace entire multi-line functions while omitting docstrings and comments inside `search_block`, failing exact verbatim matching (`orig_text.count(search_block) == 1`).
6. **Attempt 7**: Even with minimal replacement guidance in prompts, models occasionally struggled to align the exact verbatim bounds of the defect when functions contained docstrings, leading to repeated retry cycles.

### 1.2 Core Architectural Insight: Separation of Localization from Replacement
Requiring a small local LLM to reproduce verbatim source code for localization is fundamentally fragile:
- The model must accurately regurgitate unchanged docstrings, indentation, and comments that it has only seen as prompt text.
- If the model omits a single comment or docstring line, verbatim search block matching fails closed.
- The model's primary competency is reasoning about the defect logic and generating the *replacement* statement.
- In contrast, repository intelligence tools (AST parsing, test traces, symbol indexers) can establish the exact statement-level coordinates deterministically from trusted, pinned repository files without LLM hallucination.

By separating **deterministic source localization** (performed by FORGE against pinned workspace source) from **replacement proposal generation** (performed by the model), FORGE anchors the candidate patch to ground truth while preserving fail-closed security invariants.

## 2. Architecture & Design

### 2.1 Edit Anchor Contract (`EditAnchorContract`)
The contract is defined in `app/forge/repair/anchoring.py` as a typed Pydantic model:

```python
class AnchorResolutionStatus(str, Enum):
    RESOLVED = "resolved"
    ANCHOR_UNRESOLVED = "anchor_unresolved"
    ANCHOR_AMBIGUOUS = "anchor_ambiguous"
    SCOPE_VIOLATION = "scope_violation"
    PROTECTED_PATH = "protected_path"
    STALE_REVISION = "stale_revision"
    DIGEST_MISMATCH = "digest_mismatch"

class EditAnchorContract(BaseModel):
    target_file: str
    base_commit_sha: str
    source_digest: str
    anchor_text: str
    start_line: int
    end_line: int
    surrounding_context: Optional[str] = None
    replacement_content: Optional[str] = None
    evidence_ids: List[str] = Field(default_factory=list)
    finding_id: str
    status: AnchorResolutionStatus = AnchorResolutionStatus.ANCHOR_UNRESOLVED
    rejection_reason: Optional[str] = None
```

Key guarantees:
- **Pinned Ground Truth**: `base_commit_sha` and `source_digest` (SHA-256) lock the anchor to the immutable repository state.
- **Line Range Coordinates**: 1-indexed `start_line` and `end_line` pinpoint the exact statements identified by deterministic AST analysis.
- **Actionable Status**: If resolution fails, a typed status (`SCOPE_VIOLATION`, `ANCHOR_AMBIGUOUS`, etc.) and descriptive `rejection_reason` explain why.

### 2.2 Deterministic Source Anchor Resolution (`resolve_source_anchor`)
The resolution pipeline executes against trusted local repository files:
1. **Path Safety & Containment**: Rejects empty paths, root paths, path traversals (`..`), absolute paths, and symlink escapes via `verify_workspace_containment`.
2. **Protected Path Policy**: Enforces `ProtectedPathPolicy.is_protected` (`AGENTS.md`, `README.md`, `.gitignore`, `pyproject.toml`, `.github/*`).
3. **Scope Enforcement**: Rejects target files outside the finding's declared or authorized scope.
4. **Target File Existence**: Verifies that the target file exists as a regular file in the target repository.
5. **Revision Drift & Digest Validation**: Verifies that Git HEAD matches `base_commit_sha` and file content matches `expected_source_digest` (when provided).
6. **AST-Grounded Statement Localization**:
   - Inspects reproduction test trace evidence to find failing test assertions.
   - Parses the test file AST to find the failing test method and target function call (e.g. `divide(...)`).
   - Parses the target implementation file AST to locate the target function definition.
   - Traverses the function body AST to find candidate defect statements (e.g., conditional branches `ast.If` or return statements `ast.Return`).
   - Identifies exact statement line coordinates (`stmt.lineno` to `stmt.end_lineno`).
7. **Unambiguous Text Extraction**:
   - Extracts exact un-numbered statement lines from the file (`raw_lines[start - 1 : end]`).
   - Verifies uniqueness (`raw_text.count(anchor_text) == 1`).
   - If ambiguous, attempts safe 1-line context expansion; if still ambiguous, fails closed with `ANCHOR_AMBIGUOUS`.
8. **Orientation Context**: Attaches surrounding lines (up to $\pm 3$ lines) with 1-indexed line numbers for human and model orientation.

### 2.3 Deterministic Patch Construction (`construct_patch_from_edit_anchor`)
Given a verified `EditAnchorContract` and replacement content:
1. **Anchor Status Check**: Ensures `anchor.status == AnchorResolutionStatus.RESOLVED`.
2. **Non-Empty / Non-Whitespace**: Rejects empty or whitespace-only replacements.
3. **No-Op Prevention**: Rejects replacements identical to `anchor.anchor_text`.
4. **Structural & Indentation Consistency**:
   - If the anchor is an internal statement block (does not start with `def `, `class `, `async def `), rejects replacements that define entire functions or classes (`def `, `class `).
   - Verifies that replacement indentation matches or exceeds anchor indentation, preventing block-level structural corruptions.
5. **Fresh Content Digest Verification**: Recomputes SHA-256 of the target file on disk to guarantee zero concurrent modification since anchor resolution.
6. **Unified Diff Synthesis**: Delegates to `construct_unified_diff_from_search_replace` using Python standard `difflib.unified_diff`, guaranteeing standard headers (`--- a/...`, `+++ b/...`), valid hunk headers (`@@ -L,S +L,S @@`), and column-0 markers (`+`, `-`, `' '`).
7. **In-Memory Applicability & Syntax Check**: Performs in-memory patch application and Python AST compilation (`ast.parse`) without touching the target repository.

### 2.4 Repair Planner Integration (`RepairPlanner`)
In `app/forge/repair/planner.py`:
- Before prompt assembly, `resolve_source_anchor` is invoked. If an anchor violation occurs (scope violation, protected path, stale revision, digest mismatch), planning fails closed immediately.
- If an anchor is successfully resolved, `_build_prompt` injects a dedicated, passive untrusted data section:
  ```
  === DETERMINISTICALLY RESOLVED SOURCE ANCHOR (DATA ONLY - REFERENCE) ===
  Target File: calculator.py (lines 25-26)
  Context:
     22:     """
     23:     # Defect: returns 0.0 instead of raising ZeroDivisionError.
     24:     # Expected behavior: raises ZeroDivisionError when b == 0.
     25:     if b == 0:
     26:         return 0.0  # Defect: should raise ZeroDivisionError("division by zero")
     27:     return a / b
     28:
  Target Statement to Replace (exact un-numbered lines):
  ```
- If the model provides a structured search block that fails exact matching due to omitted docstrings or comments, but has provided a valid statement-level `replace_block`, `RepairPlanner` falls back to grounding the patch via `construct_patch_from_edit_anchor`.

## 3. Strict Safety & Security Invariants

1. **Immutable Ground Truth**: Repository source code on disk at the pinned commit SHA is the sole authoritative ground truth. Model hallucinations or reconstructed code snippets are never treated as authoritative.
2. **Target Repository Immutability**: All anchor resolution, diff synthesis, and syntax verification execute in-memory or within isolated disposable scratch workspaces. The target repository remains completely unmodified.
3. **No Fuzzy Matching or Silent Expansion**: FORGE never performs fuzzy text matching, whitespace stripping, or silent expansion of edit ranges. Matching is strictly exact and unambiguous.
4. **Fail-Closed Principle**: If an anchor cannot be resolved unambiguously, or if replacement content introduces syntax errors, the pipeline halts with explicit, actionable rejection reasons.
5. **Fail-Secure Provider Policy**: Local Ollama remains strictly on `http://localhost:11434/v1` with `FORGE_ALLOW_CLOUD_FALLBACK=false`. Zero cloud routing or paid API dependencies are permitted.
6. **Mandatory Human Approval Gate**: Workflow state transitions stop at `AWAITING_HUMAN_REVIEW`. No automated commits, branch pushes, pull requests, merges, or deployments are permitted.
